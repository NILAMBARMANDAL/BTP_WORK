# Production dependencies for the Render (CPU-only) ml-service deployment.
# NOT the same as ../pyproject.toml / ../uv.lock (the source of truth for
# local dev, CI, and the institute-GPU/large-v3 research configuration).
# This file deliberately excludes dev/research-only tooling that the live
# web deployment never needs at request time (mlflow, zenml, remotezip,
# pytest, gTTS) — see ARCHITECTURE.md "Deployment": the experimental
# pipeline is kept independent from the production web deployment so the
# production image stays small and its build stays fast on Render's build
# machine. Re-run the real (non-proxy) evaluation/experiment scripts from the
# repo root under `uv`, never against this image.
#
# Torch is installed separately in docker/ml-service.render.Dockerfile from
# PyTorch's CPU-only wheel index (https://download.pytorch.org/whl/cpu) —
# NOT listed here, to avoid pip resolving the much larger CUDA build from the
# default index. This is the one deliberate difference from the institute
# L40 / local-dev GPU path (pyproject.toml's cu121 torch), per
# ARCHITECTURE.md "Render ML service" — model size/device/compute type stay
# configurable via WHISPER_* env vars, not hardcoded, so switching back to a
# GPU host later is a config change, not a code change.
